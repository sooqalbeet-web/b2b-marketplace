# سوق البيت (SOOQ AL BEET) — منصة جملة متعددة المصانع والمشترين

منصة على غرار Made-in-China: المشترون يطلبون عروض أسعار (RFQ) من المصانع، يتفاوضون على السعر،
ثم يتحول العرض المقبول إلى طلب يُتابع عبر الإنتاج والجودة والشحن.

## التقنيات
Next.js 15 (App Router) · Prisma + PostgreSQL · JWT (jose) في كوكي httpOnly · Tailwind 4

## التشغيل
```bash
cp .env.example .env        # ضع DATABASE_URL و AUTH_SECRET
npm install
npx prisma migrate dev --name init
npm run db:seed             # بيانات تجريبية (كلمة السر: Password123!)
npm run dev
```

## الأدوار
- **CLIENT (مشترٍ):** تصفح المصانع، طلب عرض سعر، تفاوض، رسائل، تأكيد الاستلام.
- **FACTORY (مصنع):** ملف المصنع والشهادات، المنتجات والمخزون، الرد على العروض، الإنتاج، فحص الجودة، الشحن.
- **ADMIN:** مراجعة توثيق المصانع (`/admin`).

## دورة العمل
`SENT → QUOTED → NEGOTIATION ⇄ → ACCEPTED (ينشئ Order)` ثم
`CONFIRMED → IN_PRODUCTION → QC → READY_TO_SHIP → SHIPPED → DELIVERED`

## ملاحظات قبل الإنتاج
- الرفع المحلي في `/public/uploads` للتطوير فقط؛ استبدله بـ S3/R2 (انظر `api/uploads/route.ts`).
- الواجهة عربية كاملة (RTL): `lang="ar" dir="rtl"` في `layout.tsx`، وتسميات الحالات في `src/lib/labels.ts`، وترجمة رسائل الخطأ في `src/lib/errors-ar.ts` (أي رسالة جديدة تُضاف هناك).
- الأرقام والتواريخ تُعرض بأرقام لاتينية (`ar-u-nu-latn`)؛ غيّر الثابت إن أردت الأرقام العربية.
- أُضيف مسار الأدمن وصفحاتي (`/admin`, `/quotations`, الصفحة الرئيسية) وملفات الإعداد وschema.prisma؛ باقي المسارات من ملفاتك.
- لم أستطع تشغيل `npm install` أو `tsc` هنا (لا يوجد اتصال بالشبكة)، فشغّل `npx prisma validate && npx tsc --noEmit` أول مرة.

## حقوق المستخدم (حسابي)
- `/account` ← `/account/export` (تنزيل JSON بكل بيانات المستخدم، دون كلمة المرور) و`/account/delete` (حذف بعد تأكيد كلمة المرور وكتابة «حذف»).
- الحذف إخفاء للهوية لا مسح للصفوف: يُمنع إن وُجدت طلبات نشطة، وتُرفض عروض الأسعار المفتوحة، وتُمسح الرسائل والشهادات والملفات المحلية، وتبقى الطلبات المكتملة بلا هوية. الجلسات القديمة تتوقف فوراً.
- سياسة الشحن والإرجاع حقل `shippingReturnPolicy` في ملف المصنع، يظهر في صفحة المصنع للمشترين.
- بعد سحب هذه النسخة شغّل: `npx prisma migrate dev --name account-rights-and-policy` (حقول جديدة: `User.deletedAt`, `Factory.deletedAt`, `Factory.shippingReturnPolicy`).

## الشروط والأحكام

## السجل التجاري والموبايل
- تسجيل المصنع يتطلب السجل التجاري/الصناعي والرقم الضريبي (`Factory.commercialRegNo` فريد، `taxNo`)، ويُطبَّع الرقم (أرقام عربية→لاتينية، إزالة الفراغات، أحرف كبيرة) قبل فحص التكرار؛ التكرار يعطي خطأ 409.
- رقم الموبايل مطلوب للمشترين والمصانع (8–15 رقماً مع رمز دولة اختياري) في `src/lib/validators.ts`. لا يوجد تحقق برمز SMS بعد.
- الرقمان لا يُعدّلان بعد الحفظ (المصانع القديمة بلا أرقام تستطيع إدخالهما مرة واحدة من الملف)، وطلب التوثيق يتطلبهما، وتظهر للأدمن مع الهاتف، وتُمسح عند حذف الحساب فيُفرَّج السجل.
- بعد السحب: `npx prisma migrate dev --name registry-and-tax-numbers`.

## الأرقام اللاتينية وتوثيق البريد
- الأرقام اللاتينية (0-9) فقط في الهاتف والسجل والرقم الضريبي ورمز التحقق؛ الأرقام العربية ترفضها الواجهة البرمجية برسالة واضحة ولا تُحوَّل بصمت. (إزالة الفراغات وتوحيد حالة الأحرف في السجل ما زالت تُطبَّق لكشف التكرار.)
- رمز التحقق من 6 أرقام يُرسل **بالبريد الإلكتروني**: صالح 10 دقائق، 5 محاولات، انتظار 60 ثانية بين الإرسالات، ويُخزَّن مجزّأً (HMAC) لا نصاً.
- الحساب غير الموثّق لا يستخدم الواجهات المحمية ويُحوَّل إلى `/verify-email`؛ يسمح له فقط بصفحات `/account` (تصدير/حذف).
- اضبط `SMTP_*` و`MAIL_FROM` في `.env`؛ بدونها في التطوير يُطبع الرمز في سجل الخادم، وفي الإنتاج يفشل الإرسال عمداً.
- المستخدمون الموجودون قبل هذا التحديث (`emailVerifiedAt` فارغ) سيُطلب منهم التوثيق عند الدخول التالي.
- بعد السحب: `npm install` ثم `npx prisma migrate dev --name email-verification`.
